A text version of every scene is below the video.

No sound. About 1 minute.

Download the video (MP4, about 4 MB)

The Android part was recorded on an emulator and the iOS part on a Simulator, both scanning Swipewalk's made-up sample app. Parts that were sped up are labelled on screen ("Sped up" with the factor). The report frames show the saved HTML report, displayed outside the app. Automated checks find only some issues; manual testing is still required.

What the video shows

This list is a text version of the video.

  1. 0:00-0:02. The Swipewalk desktop app's New scan page. An Android emulator is chosen and the sample app's package name, org.swipewalk.buggyapp, is entered.
  2. 0:02-0:05. The scan is started. The Progress panel shows "Scanning... step 1 of 3".
  3. 0:05-0:32. The Android emulator during a real scan run with swipewalk scan --platform android --package org.swipewalk.buggyapp --screen-reader --large-text --orientation both. The phone is on the left and the current step on the right:
    • 0:05-0:07, real time: Swipewalk reads the screen over adb.
    • 0:07-0:19, sped up 1.5 times: Swipewalk moves TalkBack's focus to each control and captures what TalkBack says. TalkBack is silent while this runs, and Swipewalk does not tap or type. A green focus box appears briefly on controls, for example the search button and the email button.
    • 0:19-0:25, sped up 2.5 times: the text size is set to 200% and the screen is captured again.
    • 0:25-0:32, sped up 2 times: the emulator rotates to landscape, the screen is captured again, and it rotates back.
  4. 0:32-0:36. The report for that scan: "Automated checks found 6 WCAG issues", 9 items needing review and 4 platform advisories, with a note that manual testing is still required.
  5. 0:36-0:41. One finding: the search button has no accessible name. It shows a close-up screenshot, who is affected, and WCAG 1.1.1 and 4.1.2.
  6. 0:41-0:47. The screen-reader tab: what TalkBack said for each control, next to Swipewalk's prediction. Control 7 was spoken as "btnCancelPayment" where Swipewalk predicted "Unlabeled, Button".
  7. 0:47-0:56. The iOS Simulator (iPhone 17 Pro) during a real scan run with swipewalk scan --platform ios --bundle-id org.swipewalk.buggyapp --large-text. The screen is captured together with Apple's accessibility audit (sped up 2.5 times), the text size is set to the largest accessibility size, about 235% (sped up 2 times), and then the text size is put back (sped up 2.5 times).
  8. 0:56-1:00. The iOS report, zoomed in: the same finding (the search button has no accessible name, with who is affected) and its "Also reported by Apple accessibility audit" tag. The caption reads "The iOS report: some findings are also reported by Apple's accessibility audit."
  9. 1:00-1:03. A closing card: "Swipewalk. Scans running Android and iOS apps. Automated checks find some issues; manual testing is still required." and the address github.com/swipewalk/swipewalk.
